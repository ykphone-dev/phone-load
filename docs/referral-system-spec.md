# 옆커폰 가족/친구 추천 시스템 — 기능 사양서 (v0.1)

작성일: 2026-09-09 · 벤치마크: 알닷(uplusmvno.com), U+유모바일, 헬로모바일 다이렉트

---

## 1. 목적

- 기존 고객·매장을 추천 채널로 만들어 온라인 광고 대비 낮은 CAC로 개통 유입 확보
- 알닷 등 온라인 MVNO가 못 하는 **오프라인 매장 귀속**을 차별점으로 설계
- 추천 보상을 회선 유지 조건에 묶어 리텐션 수단으로 활용

## 2. 벤치마크 요약 — 무엇을 가져오고 무엇을 고치는가

| 항목 | 알닷 방식 | 옆커폰 적용 |
|---|---|---|
| 추천 링크 | 회원별 암호화 ID 1개 (`?rcmdId=...`) | 추천인 코드 + 매장 코드 2중 |
| 귀속 | 세션/쿠키 → 가입신청서 자동입력 (유실 잦음) | 개통 시스템 DB에 직접 기록, 수기 입력 백업 |
| 보상 | 추천인·피추천인 기프티콘 1개씩 (2~4천원) | 추천인·피추천인·개통 매장 3자 |
| 지급 시점 | 개통 익월 말 | 동일 (익월 말, 회선 유지 확인 후) |
| 리텐션 연동 | 없음 | 유모바일식: 피추천인 해지 시 추천인 혜택 중단 |
| 부정 방지 | 본인추천 금지, 1년 내 개통이력 제외, 타채널 중복 불가 | 동일 + 동일 명의 3개월 내 반복 가입·해지 차단 |
| 오프라인 | 매장 개통 제외 | **매장 개통이 핵심** |

## 3. 구조

### 3-1. 추천 링크
- 형식: `yeopkerphone.co.kr/r/{추천인코드}?s={매장코드}`
- 추천인코드: 고객 해시키(개인정보 없음)에서 파생. 매장 코드는 추천인의 개통 매장 기본값, 변경 가능
- 생성 위치: 앱 마이페이지 "친구 추천" + 매장 직원용 QR (매장 코드만 포함)
- 공유: 카카오톡 공유 버튼 기본, 링크 복사, QR

### 3-2. 랜딩 & 귀속
1. 링크 클릭 → 랜딩: "{추천인명}님의 추천이 도착했어요" + 혜택 요약 + 가까운 매장 안내
2. 랜딩에서 (a) 온라인 예약/상담 신청 또는 (b) 매장 방문 선택
3. 귀속 기록 시점: **개통 완료 시** 개통 시스템에 `referrer_key`, `store_code`, `referral_channel` 저장
4. 매장 방문 시: 추천 코드 6자리를 개통 화면에 입력 (링크 유실 대비 백업). 고객 휴대폰에 랜딩 접속 이력이 있으면 자동 매칭
5. 귀속 우선순위: 개통 시 입력 코드 > 랜딩 접속 이력(30일) > 없음

### 3-3. 보상 (초안 — 금액은 정산팀 확정)
| 대상 | 보상 | 조건 |
|---|---|---|
| 피추천인 | 개통 혜택 + 기프티콘 1 | 개통 완료, 익월 말까지 회선 유지 |
| 추천인 | 기프티콘 1 또는 포인트 | 피추천인 회선 유지 시 지급. 월 N건 상한 |
| 개통 매장 | 정산 시 추천 개통 가산 | 정산 시스템에 자동 반영 |

- 세그먼트별 차등 가능 (외국인, 기변 vs 신규, 요금제 구간)
- 추천인 보상은 **누적형** 옵션 검토: 피추천인 유지 기간에 비례 (유모바일 24개월 모델)

### 3-4. 지급 조건
- 지급일: 피추천인 개통월 익월 말일 (영업일 기준) 일괄
- 지급 시점 기준 제외: 피추천인 해지·정지·번호변경·명의변경, 추천인 탈퇴
- 마케팅 수신 동의 유지 조건 (알닷 방식) — 법무 검토 후 적용
- 지급 수단: 모바일 쿠폰 대행사 API 또는 앱 포인트

### 3-5. 부정 방지
- 본인추천 차단 (해시키·명의·기기 ID 비교)
- 동일 명의 3개월 내 가입·해지 2회 이상 → 대상 제외
- 최근 12개월 내 옆커폰 개통 이력 → 피추천인 제외
- 추천인 월 상한 (예: 10건), 초과분은 수동 심사
- 커뮤니티 대량 유포 링크는 허용하되 매장 코드 없는 건은 별도 채널로 분류

## 4. 데이터 모델 (요약)

```
referral_link      : link_id, referrer_key, store_code, created_at, status
referral_visit     : visit_id, link_id, device_fp, visited_at
referral_attribution: activation_id, referrer_key, store_code, source(link|code|visit), matched_at
referral_reward    : reward_id, activation_id, target(referrer|referee|store), amount, status, paid_at, void_reason
```
- 개인정보는 개통 시스템에만. 추천 테이블은 해시키만 보유
- 앞서 정한 ERP/DB 구조와 동일한 원칙

## 5. 화면 / 접점
1. 앱 마이페이지 — 친구 추천 (링크 생성, 공유, 내 추천 현황: 접속·개통·지급 상태)
2. 추천 랜딩 페이지 (모바일 웹)
3. 매장 개통 화면 — 추천 코드 입력 필드 + 자동 매칭 표시
4. 매장 QR 포스터 (매장 코드 링크)
5. 본사 관리자 — 추천 현황 대시보드, 지급 승인, 부정 의심 목록

## 6. 지표
- 추천 링크 생성률 (개통 고객 대비)
- 링크 클릭 → 개통 전환율
- 추천 개통 비중 (전체 개통 대비, 매장별)
- 추천 유입 CAC vs 온라인 광고 CAC
- 추천 개통 6개월 유지율 vs 일반 개통

## 7. 단계

| 단계 | 범위 | 기간(안) |
|---|---|---|
| 1 | 링크 생성·랜딩·개통 시 코드 입력·귀속 기록·관리자 목록 | 4주 |
| 2 | 자동 지급(쿠폰 API 또는 포인트)·매장 정산 반영·부정 방지 룰 | 4주 |
| 3 | TM 재방문 엔진 연동 (재개통 임박 고객에게 추천 링크 자동 발송)·누적형 보상 | 이후 |

## 8. 결정 필요 사항
- 보상 금액과 3자 배분 비율
- 추천인 보상: 1회성 기프티콘 vs 유지 연동 포인트
- 마케팅 동의 조건 부과 여부
- 파일럿 지역·매장 수
